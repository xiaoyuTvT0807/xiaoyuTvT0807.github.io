05版本对比（diff）修复

你提到「diff 对比你也要修一下」。我实际打开跑了一遍，定位到 3 个真实缺陷 —— 不是观感偏好问题，是排版错误。三个方案中全部已修复，且修复方式一致。

BUG 1

对比箭头「→」被推到整行最右，且字号退化成 8px

根因：原 CSS 里 .fpair .arrow 是无上下文限定的选择器， 而另一条 .sel-btn .arrow{margin-left:auto} 作用于所有 .arrow。 diff 明细里的箭头同时命中两者，被 margin-left:auto 顶到容器最右侧， 并继承了下拉按钮的 font-size:8px。结果是「旧值 ……（整行空白）…… → 新值」被拆散， 方向和对应关系完全读不出来。

修复前
状态 即将上线 →
修复后
状态 即将上线 → 进行中

修复：把 .fpair .arrow 与 .diff-top .darrow 的样式 显式限定作用域，重置 margin-left:0、字号回到 12px， 让箭头回到文本流中间，恢复「旧 → 新」的阅读顺序。

BUG 2

旧值删除线只有 1px 且半透明，中文笔画密处几乎看不见

根因：.pv.old 用了 text-decoration:line-through 配合 rgba(229,72,77,.5)。浏览器按字号自动决定线宽，12px 字号下只有 1px； 半透明红叠在中文密集笔画上，肉眼基本无法分辨「这是旧值」还是「被划掉」。 叠加 BUG 1 的箭头错位后，整行语义进一步崩坏。

修复：显式指定 text-decoration-thickness:2px、 text-decoration-color 提亮到 55%–62% 不透明度， 并加 text-decoration-skip-ink:none 避免笔画交叉处断线； 同时给旧值加浅红底、新值加浅绿底与加粗，从「颜色 + 底色 + 线形」三重区分。

BUG 3

旧值/新值贴合无空隙，空字段名留白，且对比无差异时毫无反馈

根因：明细行 .frow .fv.fpair 仅 8px 间距，旧值与新值几乎连成一段； 字段名 .fk 为空时该列塌陷成空白（截图里可见「状态 → 值在右侧飘着」）； 另外当两个版本完全没有差异时，页面只渲染出无内容的卡片，没有一句「无变更」的说明。

修复：新旧值间距提到 12–14px 并各自加内边距与浅底形成区块感； 空字段名用 :empty::before 补一个 值 占位，保证列对齐； C 方案进一步把明细改为 grid 两列，字段名列宽固定， 并新增 .diff-empty 空态样式，为无差异场景提供明确反馈。

第二轮：对比视图重写（方案 A 已落地）

上面三处是「修 bug」。你选了方案 A 之后，我又把整个对比页按 选版本 → 看汇总 → 筛模块 → 看明细 的顺序重做了一遍，目标是不滚动就能知道变了什么、变了多少、在哪：

环节原来的做法现在
信息层次 一上来就是一长串嵌套明细，没有总量概念 顶部变更汇总条：新旧版本条目数 + 共 N 处变更 + 新增/删除/修改三个可点选的计数块
定位模块 无；要在长列表里滚着找 模块筛选条只列 10 个模块（不设「全部」这一档），每个带变更数量徽标、零变更自动置灰； 进入即落在第一个有变更的模块上，不用先点一次
找具体条目 无 关键词搜索（名称 / 字段 / 旧值 / 新值全量索引）， 自动跨全部模块查找，无匹配给明确提示，清空后回到原模块
呈现形式 嵌套展平的「字段：旧 → 新」单行流 / 三列对照表，长文本与空字段名导致对齐错乱 卡片墙：一个变更项一张卡片，网格自适应排列，与主页车辆卡片同一套视觉语言
展开方式 只有一层折叠；展开后全部铺开 只有变更卡片一层折叠：模块分区恒展开、不设三角箭头 —— 既然内容本来就要给人看，就别再多一次点击。 卡片可反复点开、可同时开多张，点开后原地跨满整行；点头部收起，点正文不收起（保留文本选择）。 卡片正面先给 2 条「旧 → 新」预览，不点开也能扫到改了什么
字段对照 表格行 字段卡网格：一张卡一个字段，上旧下新；旧值红底 + 2px 删除线，新值绿底加粗，空值 —
性能 一次性渲染全部明细 对照表懒渲染——点开哪一项才生成那一项的表格，打开过的不重复生成
操作 切换版本要重走整个流程 ⇄ 交换新旧版本；刷新数据清掉两个版本缓存重读（原实现的刷新是无效代码）

顺带修掉的一个隐性 bug

原来的「刷新数据」按钮执行的是 delete CAR_INDEX_cacheFlag(v) —— 对一个函数做 delete， 既清不掉数据缓存，还会把车辆索引重置。现在改成遍历清除 DATA_CACHE 里该版本的全部条目。

06点击与跳转逻辑优化

原来是「一堆 div 挂 onclick」，能点但不好用：新标签页打不开、链接复制不出去、键盘完全够不着、 移动端点了侧栏还得再点一次才收起。这一轮全部改成浏览器原生语义的行为，三套方案一致。

位置优化前优化后
车辆 / 地图 / 道具等卡片 <div> + JS 监听点击，不能新标签页打开、不能复制链接、中键无效 改成真链接 <a href="#/veh/10000">：支持中键 / Ctrl+点击 / 右键「在新标签页打开」/ 复制链接地址，浏览器后退键回到列表
键盘可达性 只有少数按钮能 Tab 到，卡片整体不可聚焦 所有可点元素统一加 tabindex="0" + .tap，Enter / 空格触发点击；:focus-visible 给 3px 描边，不干扰鼠标用户
路由跳转 切视图后滚动位置残留，停在上一页的中段 hashchange 统一收口：重新渲染 → 主区滚动回顶部 → 移动端抽屉自动收起 → 重新探测图片命名空间
移动端侧栏抽屉 打开后必须再点一次汉堡按钮才关 点侧栏与主区以外的任意处即关闭（捕获阶段委托）；切换路由也会自动关闭
版本对比卡片 点卡片任意位置都折叠，想复制新值文本一碰就收 点头部 / 底部 / 摘要区折叠，点正文内容不折叠（stopPropagation），可以正常选中复制；开合可无限重复
车辆皮肤切换 切换皮肤直接改 src，切换瞬间闪白 hero 图复用同一个 <img> 节点，先 opacity:0 再换图，加载完成后淡入；已缓存图片直接显示不闪

这些改动都在 index.html 的业务逻辑里，三份文件逐字符一致（除主题标记与样式表引用外）， 所以换方案不会带来任何交互差异。

07图片显示优化（未上传图片也已就绪）

你现在还没上传图片，但图片链路已经整条打通：把文件丢进目录就显示，不放就自动占位， 不会出现破图、不会留白、也不会刷出上百条 404。三套方案共用同一套实现。

怎么放图片

每个方案目录下都有一个 ace/img/，把图片直接放进去即可，文件名跟数据里保持一样：

  • 车辆：10000_b.png（大图）、10000_m.png（中图）、10000_s.png（小图）
  • 地图：Loading_10005.webp 之类的小地图资源
  • 称号 / 道具 / 芯片：achievement_01_01.png 这类图标资源

放好刷新页面即可，不需要改任何代码。目录里留了一份 放图片到这里.txt 作说明。

做了什么

机制说明
字段名自动识别 pickImg() 按优先级自动找图片字段：图标b / 图标m / 图标s / 图标 / 大图 / 小图 / 加载图资源 / 小地图资源 / 主图标，找不到再递归进嵌套对象里找。数据里换了字段命名也不用改代码
命名空间探测 按视图（车辆 / 地图 / 道具 / 称号…）分别探测，每个命名空间只发 1 次请求判定有没有图片。没有图片时整个视图 0 张 img、0 条额外 404；有图片时才批量渲染 —— 避免 211 张卡片刷出 211 条 404
占位符兜底 没有图片时显示首字母渐变块（按品级着色），卡片网格依旧整齐，不会出现空白方块或破图图标
淡入 + 自愈 图片默认 opacity:0，load 后 0.28s 淡入（load/error 不冒泡，用捕获阶段监听）；单张图 404 时自动移除该节点、退回占位符，不影响同页其它图
裁剪方式分场景 缩略图 / 头像用 object-fit:cover（填满不留白），详情页主图用 contain + 内边距（不裁切、不变形）

懒加载 全部 loading="lazy" decoding="async"，几百张图也不会拖慢首屏

怎么用

三个目录各自独立、可直接部署：

  • 方案A-纯净白瓷/ — 最终交付版本：index.html + theme.css + base.css + ace/
  • 方案B-纸感极简/ — 同结构，仅 theme.css 不同
  • 方案C-数据仪表/ — 同结构，仅 theme.css 不同

每个目录都自带完整数据，整个目录拷到任意静态服务器即可运行，用浏览器打开需经 HTTP 访问 （因为数据靠 fetch 读取）。三份 index.html 的业务逻辑逐字符一致， 只改了两处：样式表引用，以及 <body> 上的主题标记； theme.css 里的版本对比（第 9 节）与图片显示（第 7.5 节）两段也已同步替换， 只是把颜色映射到各自主题变量。三套方案 11 个视图 × 桌面 1440 / 移动 390 已回归： 0 横向溢出、0 页面错误、点击与跳转行为一致。想换方案就是把目录换掉，不需要动任何数据文件。

base.css 是原站样式原样保留的基线，theme.css 在其后覆盖。 这样即使以后原站逻辑更新，只要把新的样式文件替换为 base.css， 三套主题依然生效 —— 主题与逻辑完全解耦。
